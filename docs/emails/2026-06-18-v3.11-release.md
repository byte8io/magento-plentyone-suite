# Mage2Plenty v3.11 - Bidirectional Bundle Orders

## What's New

- **Bidirectional bundle orders** - PlentyONE sets now import as native Magento bundle products, and Magento bundle orders now export as proper PlentyONE sets (a bundle parent plus components linked by a `bundle` reference) instead of flat, unrelated line items.
- **Price-type mirroring** - Pricing follows each side's model: fixed bundles price the parent, dynamic bundles price the components. Exactly one side ever carries the price, so totals never double-count and **per-component VAT is preserved** (a zero-rated item inside a bundle keeps its own rate).
- **Set-export on by default** - The **Export Bundle Components** profile setting now defaults to enabled for new profiles. Existing profiles keep their saved setting - no data patch, no change to live behaviour.
- **Fixes** - Property group export no longer aborts on a null language; the item and stock mapping CLIs are now Adobe Commerce staging aware.

## Post-Upgrade Notes

This release **ships no schema changes** - bundle linkage travels over the PlentyONE API and reuses the existing order mirror tables.

- **Export Bundle Components defaults to on for new profiles only.** Existing profiles are untouched; enable the toggle on an order-export profile to adopt set-export there.
- **Bundle import is automatic**, provided the matching Magento bundle product (and its selections) exist.
- If a single inbound order contains two bundles that share a component SKU, the importer reports it clearly rather than guessing.

Run `setup:di:compile` (the export pipeline gains a new batch generator) and `cache:flush` after upgrading.
