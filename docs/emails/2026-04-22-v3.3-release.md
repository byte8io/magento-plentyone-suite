# Mage2Plenty v3.3 - Correct VAT Discount Export, Safer Order Claims & Import Hardening

## Highlights

- **Correct VAT on discounted order lines** — Stores with Catalog Prices = Including Tax no longer see double-applied VAT on cart-rule and coupon discounts exported to Plenty. Invoice totals in Plenty now match what the customer paid in Magento, with no config change required.
- **Admin re-export of completed orders restored** — The Export and Mass Export buttons work again for orders in `complete`, `success`, `new`, `pending_collect`, `skipped`, and NULL states. Previously these raised a misleading "Skip: Order claimed by another process" message.
- **Configurable item import no longer crashes on null names** — Mass import of configurables continues cleanly when a child product's store-scoped name is null instead of terminating with a TypeError.

## What's New

- **Price-basis-aware discount export** — `Item::buildItemAmountsRequest` now consults `tax/calculation/price_includes_tax` (Catalog Prices) to decide whether to gross up the per-unit discount. The previous discriminator (`tax/calculation/discount_tax`) did not reflect how Magento actually stores `base_discount_amount` and produced wrong totals on common EU setups.
- **New `UpdateSalesOrderStatusInterface::claim()` method** — Atomic claim uses a negative predicate (`NOT IN (...) OR IS NULL`), blocking only orders actively being processed. Third-party implementers of this interface need to add the new method.
- **Store-scoped tax config lookup in Promotion generator** — Cart-level coupon export now reads `tax/calculation/discount_tax` at the order's store scope, respecting per-website overrides on multi-site installations.
- **"None" option in Magento price attribute dropdown** — Admins can now explicitly clear a price mapping in the item import profile instead of being forced to pick the first attribute in the list.

## Bug Fixes

- Fixed TypeError in `ConfigAttribute::generate` when a configurable child's product name is null for a given store
- Fixed `StoreConfig::buildStoreData` silently ignoring the per-mapping `LOCALE` field due to an undefined `$item` reference
- Fixed profile ID not propagated to collect services (`CategoryCollect`, `StockCollect`, `OrderCollect`) in schedule queue processors
- Fixed order export claim wrongly rejecting `complete`, `success`, `new`, `pending_collect`, `skipped`, and NULL source statuses
- Fixed double VAT applied to order line discount when Catalog Prices is set to Including Tax

## Post-Upgrade Notes

No Magento or Plenty config changes are required. If you previously flipped `tax/calculation/discount_tax` to `1` as a workaround for the v3.2.x discount regression, you can keep or revert that setting — exported totals will be correct either way.

If you maintain a custom `UpdateSalesOrderStatusInterface` implementation, add the new `claim(int $salesOrderId, string $newStatus, array $blockedCurrentStatuses): int` method. The existing `executeConditional()` signature is unchanged.
