# Mage2Plenty v3.4 - Item Mapping Integrity, Stock Visibility & Storage Hygiene

## Highlights

- **Item mapping integrity hardened** — Batch responses align by SKU/externalId; writes gated by SKU↔number invariant. Closes the 2026-05-04 alignment gap.
- **Scheduled integrity check** — Opt-in cron runs three SQL invariants and emails on mismatch. New `plenty:item:check-integrity` CLI for ad-hoc runs.
- **Zero-qty products visible in storefront** — Initial stock import now creates the MSI source-item row at 0 qty, instead of leaving products hidden.
- **Orphaned reservations cleared** — `client_reserved` rows from PlentyONE-unassigned warehouses are removed automatically (500/run safety cap).

## What's New

- **`plenty:item:purge-orphans` CLI** — Removes PlentyONE items with no matching Magento SKU. Dry-run, limit, and collect-first flags.
- **Item-mapping data integrity admin group** — `Plenty > Item Config > Data Integrity`. Default schedule `0 3 */2 * *`, logs to `var/log/plenty-item-integrity.log`, alert email on mismatch.
- **Order storage cleanup (opt-in)** — `Plenty > Order Config > Storage Cleanup`. Prunes `plenty_order_entity` older than retention window (default 90 days, minimum 30) in batched deletes.
- **Stale `plenty_stock_entity` pruning** — After a clean one-time full collect, rows older than the cycle-start cutoff are removed (50% safety threshold).
- **Export queue drains correctly** — Export schedule honours `process_batch_size`; parent/standalone products no longer stuck in `pending`.

## Bug Fixes

- Fixed response alignment by SKU/externalId in PIM and Item batch executors.
- Fixed `SaveProductMappingPostProcessor` writing incorrect mapping IDs — now two-pass collect/verify with SKU↔number gating.
- Fixed `REQUEST_INDEX` advancing per resource instead of per pushed item in batch requests.
- Fixed `inventory_source_item` row not created at 0 stock, leaving products invisible to MSI.
- Fixed stale `client_reserved` reservations from PlentyONE-unassigned warehouses making products unsalable.
- Fixed `plenty_item_export_queue` rows stuck in `pending` for parent/standalone products that completed without errors.

## Post-Upgrade Notes

Run `bin/magento plenty:item:check-integrity` once after upgrade to surface any pre-existing mapping mismatches — the executor fix prevents new mismatches but does not retroactively repair old rows.

Optionally, enable the new Data Integrity and Storage Cleanup admin groups; both are disabled by default. Stock-visibility and reservation-cleanup fixes apply automatically on the next run.
